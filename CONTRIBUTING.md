# Как предложить изменение

Спасибо, что хочешь помочь. Дубль делает один человек и несколько помощников, поэтому небольшие, понятные правки принимать проще, чем большие.

## Прежде чем писать код

- Для заметной функции сначала открой обращение («Предложить функцию») и опиши, какую задачу решаешь. Так мы не потратим твоё время зря.
- Принцип проекта: **проще для любителя**. Функция попадает в программу, только если делает озвучку проще. Ручной монтаж, спектральные редакторы, клонирование голоса и подделка движения губ не нужны (см. «Чего здесь нет» в [docs/ABOUT.md](docs/ABOUT.md)). Лишние настройки прячем или не добавляем: автопилот должен справляться сам.
- Багфиксы и правки текста можно сразу присылать pull request'ом.

## Как собрать и запустить

См. «Запуск для разработки» в [README](README.md) и [docs/BUILD.md](docs/BUILD.md). Устройство проекта — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Проверки перед pull request

```bash
# движок (из папки engine/, нужен ffmpeg в PATH)
.venv/bin/pytest -q -m "not slow" --ignore=tests/e2e

# интерфейс (из папки app/)
npx tsc --noEmit
npx vitest run
pnpm check:api         # типы API не устарели; нужен engine/.venv
```

`slow` и `tests/e2e` требуют нейросетей и скачанных фильмов (`samples/fetch.py`), их запускать не обязательно. CI прогоняет быстрые тесты на Linux, macOS и Windows.

## Правила кода

- **Контракт данных** — `engine/src/dubl_engine/models.py` и роуты FastAPI. Типы интерфейса генерируются из них: поменял модель или роут — запусти `cd app && pnpm gen:api` и добавь в коммит изменения `docs/openapi.json` и `app/src/api/schema.gen.ts`. Руками `schema.gen.ts` не правим. У каждого роута должен быть `response_model` или тип возврата.
- Тяжёлые библиотеки (torch, faster_whisper, demucs и подобные) импортируем внутри функций, чтобы движок запускался и проходил быстрые тесты без нейросетей.
- ffmpeg вызываем только через `dubl_engine.util.run_ffmpeg` и `ffprobe_json`.
- Новая Python-зависимость: добавь в `engine/pyproject.toml` с комментарием, зачем она, и проверь её лицензию (см. [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)). Лицензия должна быть совместима с GPL-3.0-or-later. Зависимости с запретом коммерческого использования не подходят.
- К новому поведению пиши тест. Медленные тесты помечай `@pytest.mark.slow`.
- Код и имена — по-английски. Комментарии могут быть по-русски.

## Тексты интерфейса

Всё, что видит человек, пишем **по-русски, живо и без канцелярита**: как объяснил бы знакомому. Не «осуществите выбор файла», а «выбери файл». Без англицизмов там, где есть нормальное слово, без жаргона звукорежиссёров (а если термин нужен, объясни его рядом). Ошибки говорят, что случилось и что делать, а не показывают сырой стек. Если правишь `docs/ABOUT.md`, пиши там только о том, что уже работает: этот файл показывается в программе как справка.

## Pull request

- Одна правка на один PR, короткое описание: что и зачем, как проверял.
- Если менял интерфейс, приложи скриншот.
- Не добавляй в репозиторий видео, аудио и чужие тексты (субтитры, расшифровки, эталоны по фильмам с несвободной лицензией). Для тестов годятся свободные фильмы Blender, см. `samples/README.md`.

## Лицензия вклада

Проект распространяется под GNU GPL v3 или новее ([LICENSE](LICENSE)).

Перед тем как влить первый pull request, бот попросит тебя принять [соглашение участника (CLA)](CLA.md). Для этого нужно оставить в PR комментарий с фразой, которую он покажет. Это делается один раз, дальше бот тебя узнаёт.

Коротко о соглашении: права на твою правку остаются у тебя. Автор проекта получает разрешение использовать её как угодно, в том числе выпускать под другой лицензией. Всё, что уже вышло под GPL, остаётся под GPL навсегда.
